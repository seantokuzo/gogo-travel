# apps/mobile — Expo/RN Conventions

- Styling is `StyleSheet.create` + `@gogo/tokens` ONLY. **No NativeWind / `className`** (ADR-004) — two styling sources of truth was a documented sibling-repo mess.
- 🔴 `testID` on every interactive element — E2E matches on them; point flows at the REAL UI. Grammar is navigation.spec §2.7: `<screen>-<element>[-qualifier]`, screen roots `<screen>-screen`, tabs `tab-bar-{key}`; raw RN interactives in `src/app`/`src/navigation` are lint-gated for testID (eslint.config.js, R-nav-22).
- 🟡 expo-router 57 VENDORS its react-navigation fork (no `@react-navigation/*` deps) — root `Tabs` export is deprecated: import `Tabs`/`BottomTabBarProps` from `expo-router/js-tabs`. Verify subpath APIs against `node_modules`, not training data.
- 🔴 Imperative `router.navigate()`/`router.push()` to a route in ANOTHER tab **silently no-ops** once inside the vendored tab navigator (sim-confirmed live, P-4 QA; jest walkthrough hit the same wall). Cross-tab jumps must go through tab-bar presses (`navigation.navigate(tabKey)` on the TAB navigator) — any "view X" button that targets another tab needs that plumbing, not a URL push. Cold/external URL entry into any tab works fine.
- 🔴 Never gate screens on state nothing sets (e.g. `activeTripId`) — the setting flow must exist; never paper over with a hardcoded demo ID.
- 🔴 Push needs an EAS `projectId` in app config or `getExpoPushToken()` silently returns `null`.
- 🟡 `crypto.randomUUID()` doesn't exist in RN — use `react-native-get-random-values` + `uuid`, or nanoid w/ polyfill.
- 🟡 Long lists = `FlatList`/`FlashList`, never `ScrollView` + `.map()`.
- 🟡 `expo lint` has no `--max-warnings 0` cap (flag pass-through undocumented); every other package is zero-warning — don't let mobile warnings accumulate.
- Wire types come from `@gogo/shared` — no local redefines. No `any`, no `console.log`.
- Routes live in `src/app/` (expo-router, typed routes on). Server state = TanStack Query; client state = Zustand.
- Deps: ALWAYS `npx expo install <pkg>` (never bare add) and `npx expo-doctor` before relying on a native module.
- TypeScript here is pinned by the Expo template (`~6.0.3`) — independent of the root TS 5.9; don't "align" it.
- 🟡 jest is pinned `~29.7.0` because jest-expo 57 pins the jest-29 family internally (`babel-jest ^29`, `@jest/globals ^29`, …); jest 30 crashes the preset — don't "helpfully" bump (same deal as the TS `~6.0.3` pin). Verify `npm view jest-expo@<ver> dependencies` before ever touching it.
- `app.json` `plugins` entries are added by `expo-doctor`/`expo install --fix` for plugin-bearing deps — tool-driven, not hand-curated; JSON can't carry comments, so the rationale lives here.
- 🔴 EXCEPTION: the `expo-location` plugins entry is DELIBERATELY hand-curated (explicit `false` props) — it enforces the P-8 foreground-only location lock. Never reduce it to a bare string: a bare entry lets `withLocation` defaults silently reintroduce `NSLocationAlways*`/`NSMotion` plist keys.
- Test placement: screen tests → `src/__tests__/`; module/component tests → co-located next to the source file.
- 🔴 **RNTL v14 made `render`/`fireEvent`/`renderHook`/`act` ASYNC — `await` every one.** An un-awaited `fireEvent.press(...)` / `act(() => …)` leaves a floating act() promise that resolves on the shared worker event loop DURING A LATER SUITE, racing that suite's `findBy`/`waitFor` → 5s timeout **only under CI's 2-core turbo contention** (green locally, red in CI — B-2 2026-07-25). The tell is **act warnings** ("overlapping act() calls" / "act(async) without await" / "not wrapped in act"). **Pre-merge gate: `CI=true pnpm --filter @gogo/mobile exec jest --ci 2>&1 | grep -cE 'overlapping act|without await|not wrapped in act' ` must print `0`** (see [[ci-faithful-pre-merge-gate]]); also run `--maxWorkers=2` to mimic the runner. Component/screen tests use an isolated `makeTestQueryClient` (retry:false, gcTime:0, staleTime:0) — never the prod `queryClient` singleton (its 5-min gcTimeouts leak across suites). EXCEPTION: renderRouter suites (real `_layout`) necessarily share the prod singleton — sanctioned reset recipe (T-6.6 R1): `afterEach { jest.restoreAllMocks(); queryClient.clear(); resetTabMemory(); clearLastViewedTrip(); }`; `clear()` does NOT remove `setQueryDefaults` — reset per-key overrides explicitly; NO `afterEach useRealTimers` in these suites (see the fake-timer note below); do NOT "fix" them onto `makeTestQueryClient` — the Law-#3 guard tests (stale-cache + fresh 404) depend on prod staleTime/refetch semantics being real. Don't "fix" a floating-act timeout by bumping the jest timeout — that masks it. Switching renderRouter suites to real timers leaves navigation `setTimeout`s as open handles (jest hangs on exit) — keep fake timers there. Mobile jest `testTimeout` is **20s** (not the 5s default): a correct 3-query screen-mount test settles in ~0.5s locally but can exceed 5s when CI's turbo runs server testcontainers + mobile jest on 2 shared cores (suite wall-time ~20s) — headroom for a choked runner, NOT masking (act-warnings=0 is the determinism guard; a real hang still trips eventually).
- 🟡 **The DS Sheet's scrim is unreachable from RNTL** (T-7.6, 2026-08-02): it sits under an `opacity: 0` `Animated.View` whose entrance value never advances under jest, so it reads as hidden-from-accessibility and no query finds it. Drive dismissal through the **close button** — same handler, queryable. Don't burn a cycle reaching for `-scrim`.
- 🔴 **RNTL won't fire a handler on a `disabled` element — so "assert nothing happened" passes whether or not your guard exists** (T-7.6 final, 2026-08-02). A pin that presses a disabled affordance and asserts no effect is vacuous: it holds with the guard ungated. Assert on the GUARDED HANDLER's effect instead (spy the callback, assert not-invoked), and pin each entry route separately — `disabled`-backed routes (button, scrim) and un-backed ones (`onRequestClose`/Android back, panResponder/swipe) fail differently. Falsify per route: ungate ONE, expect RED; a route you can't turn red isn't pinned.
- 🔴 **`git diff --stat` is BLIND to files your PR ADDS — the standard "confirm the probe applied" check silently lies on new modules** (T-7.9, 2026-08-03). Mutate a new untracked file and `git diff` prints nothing even though the edit landed, so a genuine probe is indistinguishable from a no-op mutation (the vacuous-pin flavor that already produced one false claim in this repo). **Run `git add -N .` before probing**, then `git diff --stat` sees new files too. Applies to reviewers and builders alike.
- 🔴 **Release the deferred promise in `finally`, not after the assertions** (T-7.9). The mandated "hold the request genuinely in flight" pin wedges the whole file if an assertion throws first — the mutation stays permanently in flight and the suite HANGS (10 min observed) instead of going RED, so a probe reads as a timeout rather than a discriminating failure. `try { …assert… } finally { resolve() }`. **And collect resolvers in an ARRAY when the request can fire more than once** (T-7.9 r1 fix leg): a single `release` slot strands the second in-flight promise, wedging the file (5 min observed) the same way — double-submit pins hit this by construction.
- 🔴 **A test that "proves" a fix by rejecting an already-settled promise proves nothing** (T-7.6 R2): optimistic write + rollback then flush in ONE notify batch, so the intermediate in-flight state never commits and the pin passes with the fix reverted. Two agents caught this on the same pin. Any test asserting mid-mutation UI (pending gates, in-flight holds, spinners) must hold the request genuinely in flight — a deferred promise you resolve/reject AFTER asserting — then settle it and drain. Mutation-verify every such pin: revert the prod guard, expect RED.
- 🔴 **A screen test that mocks the whole feature module (`jest.mock("@/auth")`, etc.) can't see a render-time crash in that module** — T-5.7 shipped a `useGoogleSignIn()`-throws-on-unconfigured-clientId crash (whole sign-in screen down) past all-green CI because the screen test mocked `@/auth` wholesale + jest.setup globally stubs the provider. For any screen with native/env-dependent hooks (auth, push, secure-store), keep at least ONE test that renders it through `renderRouter` with the REAL hook in its NOT-configured state and asserts no throw. Conditional hook usage → gate by RENDERING a subcomponent (`{isX() ? <Btn/> : null}`), never a conditional hook call.
- 🔴 **Never type a raw control byte into source — write the escape** (T-5.1 server, recurred T-7.5 mobile). One literal NUL makes git call the file BINARY: it vanishes from `gh pr diff` (a whole module got reviewed by 5 lanes that couldn't see a line of it) and BSD `grep` exits 1 SILENTLY, so the next agent concludes the symbol doesn't exist. tsc/eslint/`expo lint` all pass. Now guard-enforced repo-wide (`.github/scripts/check-nul-bytes.mjs`); the rule lived only in `server.md`, which is why mobile re-stepped it.
- Screens need loading/error states, safe-area + keyboard handling; consider offline for during-trip surfaces.
- Lint = `expo lint` (local flat config, not the root one). Build = `expo export --platform ios`.
